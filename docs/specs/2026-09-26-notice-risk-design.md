# 公告风险细判（两段式：标题粗筛 → 正文细判）设计

日期：2026-09-26　状态：用户已逐段确认，待审阅

## 背景与问题

现在 `jevq/judge/notices.py` 只看公告**标题**：关键词命中「减持/质押/回购/诉讼」直接判雷，否则让 Jev 按标题分类，任何一条落进雷的类别（或置信度 < 0.6）就整只否决。

问题：
- 真正在否决的多是关键词硬规则（库里回购 9 条出自关键词、1 条出自 Jev；减持 3 条、诉讼 2 条全是关键词）。
- 误杀：「控股股东承诺未来 12 个月不减持」被判减持；「回购进展」「回购注销完成」「解质押及再质押」这类常规公告被一律否决。
- 看不到轻重：减持 0.2% 已完成与控股股东拟减持 3% 被同样对待。

## 目标

- 只对**疑似雷**的公告读正文，交给 Jev 按轻重打风险分，分数过线才否决。
- 风险类别扩为十一类（见下）。
- 决策过程可追溯：面板、推送、报告都能看到每条疑似公告的类别、等级、分数、概率、是否读了正文。
- 不改变：情绪/外围/消息面（NewsJudge）逻辑；影子账户不走 Jev；三类策略（低吸、扫首板、自定义）共用同一个 `NoticeJudge`；Jev 出错 = 当日否决；不做仓位大小判断。

## 风险类别（十一类）

| 类别 | 标题关键词（第一段粗筛用） | 风险等级口径（写进 Jev 的 criteria） |
|---|---|---|
| 减持 | 减持 | 看比例、计划还是已完成、主体是否控股股东/实控人。控股股东或合计 ≥1% 的新计划 = 高；小比例或董监高零星 = 中/低；已完成、终止、承诺不减持 = 低/无 |
| 质押 | 质押 | 看质押比例、新增/补充/解押、平仓风险。高比例新增或补充质押、接近平仓线 = 高；常规小比例 = 低；解押 = 无 |
| 回购 | 回购 | 进展、完成、注销 = 低；回购终止、未按计划实施、回购后拟减持 = 高 |
| 诉讼仲裁 | 诉讼、仲裁、起诉 | 看涉案金额占净资产比例、公司是被告还是原告。大额被诉 = 高；小额或公司为原告 = 低 |
| 重组 | 重组、重大资产、发行股份购买资产 | 终止、失败、被否、收到问询 = 高；筹划、预案、推进中 = 中（停牌与兑现风险）；完成过户、实施完毕 = 低 |
| 风险提示 | 异常波动、风险提示、涨幅较大 | 普通「股票交易异常波动公告」且称无应披露未披露事项 = 低；「严重异常波动」、公司主动提示股价脱离基本面 = 中/高 |
| 监管处罚 | 立案、调查、处罚、警示函、监管函、纪律处分、问询函 | 立案调查、行政处罚 = 高；警示函、监管函、问询函 = 中；已回复且无实质问题 = 低 |
| 退市风险 | 退市、终止上市、风险警示、*ST、面值 | 一律 = 高 |
| 限售解禁 | 解禁、限售股上市流通 | 看解禁数量占流通股比例：≥5% = 高；1%～5% = 中；<1% = 低 |
| 冻结和债务 | 冻结、逾期、违约、违规担保、资金占用 | 实控人/控股股东股份冻结、债务逾期违约、违规担保、资金占用 = 高；小额 = 中 |
| 审计问题 | 非标、无法表示意见、保留意见、会计师事务所辞任、变更会计师 | 非标或无法表示意见 = 高；年中突然更换会计师 = 中 |

不单列：控制权变更（好坏参半，归「其他」）；亏损（用户确认不管）。

## 上线前对照后的收紧（2026-09-26，用户确认）

真实对照发现 Jev 给交易所强制披露的普通异动公告打中/高分，且不看时效。改由规则处理：
- 普通「股票交易异常波动」公告（标题无「严重」「风险提示」）视为例行公告：不算疑似、不问 Jev。
- 冻结和债务类的例行报表（标题含「汇总表」「专项说明」「专项报告」「专项审核」）同样视为例行公告。
- 「风险提示」类只看近 10 天（`CATEGORY_WINDOW_DAYS`），其余类别仍看 `NOTICE_LOOKBACK_DAYS`；超出窗口的计入「其余无关」。

## 流程

### 第一段：挑出疑似（`NoticeJudge`）

对一只票近 3 个月（`NOTICE_LOOKBACK_DAYS`）的每条公告：
1. 标题命中上表任一关键词 → 疑似，类别取第一个命中的类别，来源 `keyword`。
2. 否则沿用现在的 Jev 标题分类（`kind` 选择题，`CRITERIA` 扩到十一类 + 「其他」，结果缓存在 `notice_verdicts`）。落在十一类之一 → 疑似，来源 `jev_title`。
3. 关键词命中**不再直接否决**。删除 `NEGATION_KEYWORDS`、`SAFE_KEYWORDS` 补丁逻辑——「承诺不减持」「解除质押」照样进入第二段，由正文细判给出低/无。

### 第二段：正文细判（新增 `jevq/judge/notice_risk.py`）

对每条疑似公告：
1. 取正文（`notice_bodies` 缓存；未缓存则现抓；抓不到 → `body=None`）。
2. 调 Jev 一次，`state` = `{公告标题, 公告类型, 公告日期, 距今天数, 疑似类别, 正文摘要 | "未读到正文，仅凭标题判断"}`，问题：
   - `risk`：choice，选项 `高/中/低/无`，instructions「这条公告对短线（1～3 个交易日）持股的风险有多大？」，criteria 用上表该类别的口径 + 通用说明。
3. 风险分 `score = P(高)×1 + P(中)×0.6 + P(低)×0.2`（四档概率来自 Jev 返回的 probabilities，缺项按 0）。
4. 结论：`score ≥ 0.5` → 否决「高风险」；`0.35 ≤ score < 0.5` → 否决「拿不准」；`< 0.35` → 放行。阈值放 `config`：`RISK_REJECT = 0.5`、`RISK_UNSURE = 0.35`。
5. 缓存到新表 `notice_risk(id PRIMARY KEY, version, category, level, score, probs, body_read, created)`。`version` = 常量 `RISK_VERSION`（改 criteria 时 +1，旧版本记录视为未判、重新判）。

### 一只票的结论

- 任一疑似公告 Jev 调用失败 → `("error", "Jev 不可用")`（与现在一致）。
- 否则取 score 最高的疑似公告：过线 → `("reject", "{类别}·{高风险|拿不准} {score:.2f}：{date} {title}")`；都没过线 → `("pass", "公告无雷")` 或（有疑似但都低）`("pass", "疑似 N 条，均判低风险")`。
- 每只票每次检查最多细判 20 条疑似（按日期新到旧），超出记入 trace「未细判」，不视为雷。

### 正文抓取（新增 `jevq/data/notice_body.py`）

- `fetch_body(art_code) -> str | None`：GET `https://np-cnotice-stock.eastmoney.com/api/content/ann?art_code={id}&client_source=web&page_index=1`，取 `data.notice_content`，清理空白，截前 1500 字；timeout 8s；任何异常返回 None。
- `get_body(conn, id, fetch=fetch_body)`：先查 `notice_bodies(id PRIMARY KEY, text, fetched)`；没有才抓；抓到才写缓存（失败不写，下次可重试）。
- **早上预抓**：`sync_notices` 完成后，对当日股票池内近 3 个月、标题命中关键词、尚无正文缓存的公告预抓正文，8 线程，每天最多 300 条；失败只记日志，不影响交易流程。

## 显示

- **trace**（`NoticeJudge.last_trace`，写入 decisions.trace）：每条疑似 `{date, title, days_ago, category, source(keyword|jev_title), level, score, probs, body_read, excerpt(前 200 字), verdict(reject|unsure|pass)}`；非疑似只记数量 `others: N`；超出上限的记 `skipped: [...]`。
- **面板「Jev 判断」详情**：新增「公告风险」区块，疑似公告按 score 降序：类别、等级+分数、四档概率条、「已读正文 / 仅标题」标记，点开看摘要；底部「其余 N 条无关公告」。所有字符串经 `esc()`。
- **微信推送**（主账户买入）：附 score 最高的 3 条疑似及结论，例：「减持·低 0.18 放行」。
- **复盘报告**：否决理由为新格式；新增「公告风险统计」小节：今日细判条数、否决数（高风险/拿不准）、按类别计数、未读正文条数。

## 错误处理

- 正文接口失败 → 仅标题判，trace 标 `body_read=false`。
- Jev 失败 → 该票 error（当日否决），不写 `notice_risk` 缓存。
- 预抓失败 → 仅日志。
- 旧缓存：`notice_verdicts` 继续作为第一段 Jev 标题分类缓存；旧的 keyword 记录不再代表否决。

## 上线前对照（一次性脚本，不入交易流程）

`scripts/notice_risk_replay.py`：取最近 N 个交易日 decisions 中因公告被否决的主账户候选，用新流程重判（真实 Jev、真实正文），输出「旧结论 → 新结论」对照表（含类别、等级、分数、是否读到正文）。用户看过同意后才重启后台上线。

## 测试（不联网，注入假 Jev 与假正文）

- 「承诺不减持」→ 疑似 → 正文低风险 → 放行。
- 回购进展 → 低 → 放行；回购终止 → 高 → 否决。
- 重组推进中 → 中（score 0.6）→ 否决。
- 风险提示：普通异动 → 低放行；严重异常波动 → 否决。
- 分界线：0.349 放行、0.35 拿不准否决、0.5 高风险否决。
- 正文抓取失败 → body_read=false，仍能判；失败不写正文缓存。
- `notice_risk` 缓存命中不再调 Jev；`RISK_VERSION` 变化后重判。
- 任一细判 Jev 失败 → error。
- 每票细判上限 20；预抓每日上限 300、只抓关键词疑似、只抓无缓存。
- trace 结构、报告统计小节、推送包含前 3 条疑似。
- 低吸、扫首板、自定义策略原有测试不削弱（涉及公告判断结论的用例按新语义更新并注明）。
