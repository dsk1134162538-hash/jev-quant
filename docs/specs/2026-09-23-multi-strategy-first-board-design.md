# 多策略框架 + 打首板策略 — 设计文档

日期：2026-09-23
状态：待审阅
前置：`2026-09-23-jev-lowbuy-papertrade-design.md`（低吸策略，已上线运行）

## 1. 目标

1. 把低吸规则抽象成「策略」，让多套规则共用同一份行情、同一份 Jev 判断，按账户分别记账，每天并排对比净值。
2. 新增第二套策略「只做龙头、扫首板」，与低吸对比。
3. 分工不变：**规则负责选股，Jev 负责拦截**（公告排雷 + 消息面），卖出不依赖 Jev。

只给用户本人使用，仍是本地桌面程序 + 后台常驻进程，模拟盘，不接券商。

## 2. 策略与账户

| 策略 | id | 主账户（Jev 拦截） | 影子账户（不拦截） | 初始资金 |
|---|---|---|---|---|
| 低吸 | `lowbuy` | `main` | `shadow` | 各 3 万 |
| 扫首板 | `board` | `board_main` | `board_shadow` | 各 3 万 |

- 低吸沿用原账户名 `main` / `shadow`，已有数据无需迁移。
- 每个账户全仓单票（最多持有 1 只，买入用全部可用现金），与低吸一致。
- 市场情绪/外围判断全局共享；公告与消息面判断按股票当日缓存，两个策略复用同一份结果。

## 3. 策略框架

每个策略实现同一个接口（示意）：

```python
class Strategy(Protocol):
    id: str
    name: str
    accounts: tuple[str, str]                 # (主账户, 影子账户)
    fast: bool                                # 是否需要 3 秒快速循环
    def prepare(self, ctx) -> None            # 盘前：加载所需数据
    def on_minute(self, ctx, quotes, now) -> list[Fill]   # 每分钟：卖出检查 + 选股 + （慢速策略）买入
    def on_fast(self, ctx, now) -> list[Fill]             # 每 3 秒：仅 fast 策略，快速买点检查
    def sell_decision(self, pos, q, now) -> SellDecision
```

- `ctx` 提供共享服务：账本、Jev 判断器（公告/消息面，含当日缓存）、市场情绪与外围、股票池、本地收盘价、决策留痕。
- 引擎（`Engine`）变成编排者：每分钟抓一次全市场行情 → 对每个策略调用 `on_minute`；运行循环在有 fast 策略且其观察池非空时，按 3 秒节拍调用 `on_fast`。
- 低吸策略把现有逻辑原样搬进 `LowBuyStrategy`，**行为不变，现有测试全部保留**。
- 卖出永远先于买入；任何策略的异常只影响该策略本轮，不影响其他策略和卖出（沿用现有异常边界原则）。

## 4. 扫首板策略

### 4.1 题材数据
- 来源：新浪概念板块（`ak.stock_sector_spot(indicator="概念")` 列表 + `ak.stock_sector_detail(sector=label)` 成分），约 175 个概念，2026-09-23 已验证可用（0.3~0.7 秒/请求）。东方财富板块接口被拦截，同花顺无成分接口，均不用。
- 新表 `concepts(code TEXT, concept TEXT, updated TEXT, PRIMARY KEY(code, concept))`。
- 每周一盘前（或表为空、超过 7 天未更新时）串行刷新一次，请求间隔 0.5 秒，约 3 分钟；连续失败 10 次即停止并沿用旧数据。
- 刷新失败且表为空：当天扫首板策略不开新仓，面板显示提醒；卖出不受影响。

### 4.2 每分钟：挑候选进观察池
1. 用全市场报价计算每个题材中「涨幅 ≥ 5%」的成员数（只计股票池内、非 ST、行情为当日的股票）。成员数 ≥ 3 的题材为**热点题材**。
2. 在热点题材内，对成员按 **当前涨幅、成交额、近 5 日涨幅** 分别降序排名，三项名次相加为龙头分（越小越好）。
3. 每个热点题材取龙头分最好的一只，满足全部条件才进观察池：
   - 当前涨幅 ≥ 7% 且尚未封死（价格 < 涨停价）；
   - **首板**：昨日未涨停（本地收盘价：昨收 < 前日收盘价 × 1.1 四舍五入到分）；
   - 主板 60/00、非 ST、上市满 60 个交易日（沿用股票池）。
4. 观察池全局最多 5 只；进入观察池时立即做一次 Jev 公告 + 消息面判断（复用当日缓存），否决的移出并记入当日否决集。
5. 观察池里的票若回落到涨幅 < 6% 则移出。

### 4.3 每 3 秒：扫板买点
- 只请求观察池内股票的报价（一次请求）。
- 买入条件（快照同时满足）：涨幅 ≥ **9.0%**、价格 < 涨停价（未封死）、行情为当日、Jev 判断为通过（主账户）、账户有空位、时间在**扫板窗口**内。
- 扫板窗口默认 **09:30–10:30**（用户经验：早盘越早封板越强，午盘板易骗炮，尾盘板弱），作为策略参数 `scan_windows: list[tuple[time, time]]` 可调。观察池的维护（4.2）全天照常进行，只在窗口内触发买入。
- 成交价 = 快照价格；**快照时已封死（价格 = 涨停价）视为排队，记为未买到**，不补记。
- 影子账户：同样的观察池与触发条件，跳过 Jev 判断。
- 系统每 3 秒看一次，会漏掉部分瞬间封板的票，结果偏保守（少成交，不虚高）。

### 4.4 卖出（次日起，纯规则）
按优先级：
1. 当前价格 ≤ 昨收 × (1 − 3%) → **止损**
2. 当前封死涨停（价格 = 涨停价）→ **持有**
3. 今日曾封板后打开（最高价 = 涨停价 且 当前价 < 涨停价）→ **炸板卖出**
4. 当前价 ≤ 今日最高价对应涨幅 − 2 个点 且 今日最高涨幅 > 0 → **冲高回落卖出**
5. 14:55 且未封死涨停 → **尾盘清仓**
6. 其余 → 持有

- 14:55 时封死涨停的仓位**可以隔夜**，次日按同一套规则继续处理（与低吸「不隔第二夜」不同，属于该策略设计）。
- 隔夜超期规则（程序错过交易日）：开盘第一轮直接卖出，除非当时处于封死涨停。
- 涨跌停不可成交规则、费用、整手沿用账本现有实现。

### 4.5 封板时段统计（验证经验，不交易）
- 每日收盘后（15:05 写报告时）从涨停池（`stock_zt_pool_em`，含「首次封板时间」「连板数」）取当日**全部首板**（连板数 = 1），写入新表
  `board_events(date, code, name, first_seal TEXT, bucket TEXT, concept TEXT, next_open_pct REAL, next_close_pct REAL, next_board INTEGER, PRIMARY KEY(date, code))`。
- 时段 `bucket`：`早盘 09:30–10:30`、`上午 10:30–11:30`、`午盘 11:30–13:30`（含 11:00 后与 13:00–13:30 开盘段）、`下午 13:30–14:00`、`尾盘 14:00–15:00`，以首次封板时间归类。
- 次日收盘后，用本地收盘价与当日开盘价回填上一交易日各首板的 `next_open_pct`（次日开盘相对前收）、`next_close_pct`（次日收盘相对前收）、`next_board`（次日是否涨停）。
- 面板新增「封板统计」表：按时段汇总样本数、次日平均高开、次日平均收盘涨跌、次日连板率。报告附当日各时段首板数量。
- 不调用 Jev、不影响交易；拿不到涨停池只记日志。

## 5. 运行节拍
- 盘中每分钟整点：抓全市场行情（现有）→ 各策略 `on_minute`。
- 同一分钟内：若扫首板观察池非空，每 3 秒调用一次 `on_fast`；为空则休眠到下一分钟。
- 腾讯行情请求量：观察池 ≤5 只时每分钟约 20 次单请求，远低于今天触发 WAF 的量级（一分钟 3000+ 次 K 线请求）。

## 6. 留痕与展示
- 决策 trace 增加 `strategy` 字段；扫首板额外记录：所属题材、题材热度（涨超 5% 成员数）、龙头分及三项名次、触发时涨幅与是否已封死。
- 面板：账户卡片按策略分组；净值曲线 4 条线；「Jev 判断」可按策略筛选；决策明细展示「为什么是龙头」。
- 复盘报告：按策略分节列出净值、成交、检查记录。

## 7. 出错处理（沿用原则：宁可不买，不能卖不掉）

| 故障 | 处理 |
|---|---|
| 题材数据不可用 | 扫首板当天不开新仓，面板提醒；卖出照常 |
| 本地收盘价不足（无法判断首板/近 5 日） | 该股不进观察池 |
| 3 秒报价失败 | 跳过本次；不影响每分钟主循环与卖出 |
| 某策略本轮异常 | 记日志，只跳过该策略本轮 |

## 8. 测试
- 纯函数：热点题材计算、龙头分排名、首板判断、观察池进出、扫板触发与「已封死不成交」、卖出规则逐行（含炸板、冲高回落、封板隔夜、隔夜超期例外）。
- 框架：低吸行为回归（现有测试全部通过）；两个策略同一 tick 互不影响；一个策略抛异常不影响另一个的卖出。
- 运行循环：假时钟下观察池非空时 3 秒节拍、为空时分钟节拍。

## 9. 不在范围内
连板策略、逐笔/秒级行情、真实下单、用户自定义规则编辑界面（先用代码配置，验证有效后再考虑）。

## 10. 风险
- 扫板模拟漏单偏保守；真实打板的排队与滑点无法模拟。
- 两套策略、四个账户同时比较，需跑更久（建议 ≥ 1 个月）才能下结论，避免把运气当规律。
- 新浪题材接口可能变动或被限流；有周缓存兜底。
