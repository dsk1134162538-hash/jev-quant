# Jev 低吸模拟盘系统 — 设计文档

日期：2026-09-23
状态：待审阅

## 1. 目标

用模拟盘验证一套 A 股 T+1 短线低吸策略，并回答一个问题：**用 Jev 做公告、消息面、情绪、外围四项过滤，能否比不过滤赚得更多？**

不接券商、不碰真钱。衡量标准是主账户（带 Jev 过滤）对比影子账户（同规则、无 Jev 过滤）的净值差。

## 2. 范围

- 市场：沪深主板，代码以 `60` 或 `00` 开头
- 剔除：ST / *ST 股票；上市不满 60 个交易日的新股；停牌股
- 所有涨跌幅均相对**昨日收盘价**计算
- 运行时段：仅交易日

不在范围内：创业板、科创板、北交所；实盘下单；历史回测（Jev 可能见过历史走势，回测结果不可信，只做前向模拟）。

## 3. 交易规则

### 3.1 买入

| 条件 | 规则 |
|---|---|
| 价格区间 | 当前涨跌幅在 0% ~ -3% 之间 |
| 公告 | 近 3 个月（90 天）无减持、质押、回购、诉讼/仲裁类公告（亏损公告不影响） |
| 消息面 | 近 24 小时消息面不为「偏空」 |
| 买入模式 | 情绪为「偏弱/冰点」**或**外围为「偏弱」→ 只在尾盘 14:50 买入；否则盘中触及区间即可买入 |
| 仓位 | 初始资金 3 万元，**全仓单票**：最多同时持有 1 只，每笔用全部可用现金（2026-09-23 用户由「2 只各 1.5 万」改为全仓） |
| 重复买入 | 卖出后当天盘中仍可再买（含同一只），需重新过所有过滤 |
| 候选排序 | 区间内候选按**近 5 个交易日涨幅从高到低**排序（强势股回调优先），从头逐只过 Jev 过滤，买满为止；每轮最多检查 10 只，被否决的当日不再检查 |

### 3.2 卖出（次日起，纯代码，不依赖 Jev）

| 情形 | 规则 |
|---|---|
| 开盘涨 1% ~ 3% | 立即卖出 |
| 开盘涨 > 3% | 立即卖出 |
| 开盘在 -1% ~ +1% | 盘中触及 +1% 卖出 |
| 开盘跌 1% ~ 3% | 持有；盘中回到 0 轴附近（≥ -0.2%）或从日内低点反弹 1.5 个点即卖出（-2% ~ -3% 低开按同组处理） |
| 任意时刻跌到 -3% 或以下（含低开 ≤ -3%） | 立即止损 |
| 14:55 仍未触发 | 清仓，不隔第二夜 |

### 3.3 成交模拟

- 每分钟行情快照价格作为成交价（开盘前几分钟有滑点，模拟结果会略好于实盘，报告中注明）
- 开盘即涨停不可买入，跌停不可卖出，停牌不动
- 费用：佣金万 2.5（单笔最低 5 元）、卖出印花税 0.05%、过户费 0.001%
- 股数按 100 股整手向下取整；一手超过可用现金的股票（3 万本金时约股价 > 300 元）不可买
- 小资金下单笔佣金基本触发 5 元下限，一买一卖总成本约 0.12%，报告中单列费用占比

## 4. 架构

```
行情快照(每分钟) ──┐
公告 / 新闻 ───────┼─▶ 判断层 ──▶ 规则引擎 ──▶ 模拟盘账本 ──▶ 每日复盘
情绪 / 外围 ───────┘   (Jev)      (纯代码)      (SQLite)
```

| 模块 | 职责 | 依赖 |
|---|---|---|
| `data/` | 实时行情、日 K、外围指数走腾讯行情接口（A50 期货走新浪）；股票列表、交易日历、公告、新闻、涨停/跌停/炸板池走 AKShare | 腾讯/新浪 HTTP、AKShare |
| `judge/` | 封装 Jev 调用，提供四种判断；结果按有效期缓存 | Jev API、`data/` |
| `rules/` | 买卖条件纯函数：输入行情 + 持仓 + 判断结果，输出动作 | 无外部依赖 |
| `ledger/` | 模拟盘账本：持仓、成交、现金、费用；主账户与影子账户各一套 | SQLite |
| `runner/` | 交易日调度与盘中循环 | 以上全部 |
| `report/` | 收盘后生成复盘报告 | `ledger/`、`judge/` 日志 |

2026-09-23 已验证：东方财富 `push2` 实时接口（`stock_zh_a_spot_em`、`index_global_spot_em`）被服务端断开，不可用，改用腾讯 `qt.gtimg.cn`（800 只/请求约 0.15 秒，含涨跌停价）。公告按日期全市场拉取（`stock_notice_report`）并落库，个股排雷走本地查询。

## 5. Jev 判断

| 判断 | 接口 | 输入 | 输出 | 频率 |
|---|---|---|---|---|
| 公告排雷 | Choice | 单条公告标题（+摘要），回看 90 天 | 新增减持 / 新增质押 / 回购 / 诉讼仲裁 / 亏损 / 解除质押或减持完成 / 其他 | 每条公告只判一次，按公告 ID 永久缓存 |
| 消息面 | Score | 近 24 小时新闻标题 | 偏空 / 中性 / 偏多 | 每只股票每日一次 |
| 市场情绪 | Score | 涨停数、跌停数、炸板率、最高连板、主板成交额较昨日同期、涨跌家数 | 冰点 / 偏弱 / 正常 / 火热 | 每 30 分钟 |
| 外围 | Score | 隔夜道指/纳指/标普、中概金龙指数、A50 期货、前日恒指涨跌幅 | 偏弱 / 中性 / 偏强 | 开盘前一次 |

公告排雷流程：

1. 代码先做标题关键词粗筛，明显命中的直接判雷（不花钱）
2. 其余交给 Jev 分类；命中前四类任意一类 → 不买
3. 最高概率 < 0.6 视为拿不准，按有雷处理，并记录供复盘

成交额「较昨日同期」：盘中口径下与 5 日全天均值比较会系统性偏低，改为与上一交易日同一分钟的累计成交额比较；首日无历史时该项留空。

Jev 接口：`POST https://api.typesafe.ai/v1/systemone`，Bearer 鉴权，body 为 `{state, model, questions}`；Choice 返回 `choice/probabilities/confidence`，Score 返回 `score/legend/probabilities/confidence`；429/529 可重试，401/422 不重试。

## 6. 影子账户

与主账户使用完全相同的价格区间、买入模式（盘中/尾盘）、候选排序、仓位与卖出规则，唯一区别是**跳过个股层面的 Jev 过滤**（公告排雷、消息面），直接买排序最靠前的候选。两账户的差值即个股排雷的价值。两账户每日并排对比净值。

市场情绪/外围判断两账户共用，因此它的价值不在这组对比里衡量。

## 7. 出错处理

原则：出问题宁可不买，但不能卖不掉。

| 故障 | 处理 |
|---|---|
| Jev 超时/报错 | 重试一次；仍失败 → 该股当日不买 |
| Jev 整体不可用 | 停止开新仓；卖出规则不受影响照常执行 |
| 行情抓取失败 | 跳过本轮；连续 3 轮失败 → 当日剩余时间暂停开新仓，持仓在拿到行情后照常按规则卖 |
| 情绪/外围数据缺失 | 视为行情不好，只尾盘买 |

所有 Jev 调用的输入、输出、概率都落库，复盘时可追溯每一笔买入或放弃的依据。

## 8. 日程

| 时间 | 动作 |
|---|---|
| 09:00 | 加载股票池；并发拉日 K 计算全股票池近 5 日涨幅 |
| 09:15 | 外围判断 |
| 09:20 | 同步公告库（首次运行回补 90 天，约 10 分钟） |
| 09:30–11:30、13:00–15:00 | 每分钟一轮：抓行情 → 卖出检查 → 买入检查 |
| 13:00 | 再同步一次当日公告 |
| 15:05 | 记录净值，生成复盘报告 |

注：消息面判断在候选股被检查时才做（当日缓存），不做开盘前预热——开盘前不知道哪些股票会跌进区间。

## 9. 复盘报告

每日一页：当日成交明细；每笔的 Jev 判断与概率；被 Jev 否决的候选及理由；主账户与影子账户净值曲线对比；当日情绪/外围判断。

## 10. 测试

- `rules/`：把 3.1、3.2 规则表逐行写成单元测试，含边界值（-3.00%、+1.00%、涨跌停）
- `ledger/`：费用计算、整手取整、涨跌停不可成交
- `judge/`：用录制的 Jev 响应做离线测试；超时与低置信度分支
- 集成：用伪造的行情序列驱动 `Engine.tick`，核对两账户成交记录
