# 自建板块（只记录，不进交易）设计

日期：2026-10-04　状态：方向已和用户谈定，待审阅 spec

## 目标

用我们自己的口径把股票分进板块：**主业就是这个板块的产品才进，占比小的不进**。板块内排龙头 1、2、3…；用 Jev 判断板块当天行情好不好。目的是**长期记录、积累数据，验证这套分类和龙头排序有没有用**，再决定要不要用到选股上。

用户已确认：
- **只记录，不进实盘，也不影响任何模拟买卖**（不接 `board`、`rebound`、自定义策略，不改它们的候选和排序）。需要大量数据验证和积累。
- 「主业」线：该板块对应产品的**收入占比 > 50%**（用户说「大于 50% 可以」；边界值 =50% 的处理见下，默认 ≥50% 算）。
- 可以参考新浪的题材，但只当**候选来源**，成员资格不由它决定。

## 铁律：与交易完全隔离

- 新代码**不被任何策略 import**；只有后台的「收盘后记录」步骤和面板的只读页面用它。
- 记录步骤整体 try/except，出错只记日志，不影响报告、同步、推送。
- 测试断言：开启本功能前后，同一份输入下 `decisions`、`fills` 完全一样。
- 开关 `config.OWN_SECTORS_ENABLED`（默认 True，关掉 = 不抓数据、不记录、页面显示「未启用」）。

## 数据

### 1. 板块定义（`own_sectors`）
`{id, name, product_def, status, created}`。`product_def` 一句话写清核心产品，例如「电子布：用于 PCB 的玻纤电子布（含特种布、二代布）」。
- 初始种子：用户确认的清单，放 `jevq/data/own_sectors_seed.json`（首版从 2026-09-30 晚报的 14 个方向 + 电子布等整理，**由用户审**）。
- 新板块**只提议不自动生效**：晚报里出现种子里没有的板块名，写成 `status='proposed'`，面板上等用户确认/驳回；`proposed` 不参与成员计算。

### 2. 成员（`own_members`）
`{sector_id, code, tier, share, basis, source, status, checked, valid_to}`
- `tier`：`core`（产品收入占比 ≥ 50%）入板块；`related`（30%～50%，只记录不入板块，方便以后调线）；其余不记。
- `share`：对应产品收入占比。同一板块对应多个产品行时**占比相加**。
- `basis`（JSON，必存，面板可看）：数据来源、报告期、产品行名称及各自占比、或主营业务原文摘要、Jev 的判断与概率。
- `source`：`revenue`（主营构成）/ `jev`（没有构成数据时由 Jev 读主营介绍判断，`status='pending'`，用户确认后才算 core）/ `manual`（用户手工）。
- `status`：`auto` / `pending` / `confirmed` / `rejected`。面板上可确认、驳回；驳回的永不再自动加入。
- `valid_to`：成员有效期（默认下次财报披露或 90 天，取早），到期重算——主业会变，题材会退潮。

### 3. 板块日快照（`own_sector_daily`）
收盘后每个板块一行：`date, sector_id, members, strong(涨超5%), limit_up, avg_pct, amount, max_board, leaders(JSON: 龙头 1..N 的代码/名称/排名依据), article_mentioned(bool+文章标题), jev_strength(标签), jev_probs, jev_confidence`。

### 4. 已有表复用
行情/收盘价用现有 `closes`；文章用现有 `day_cache(kind='hi189')`；新浪题材用现有 `concepts` 表（只读）。

## 怎么把股票分进板块

1. **候选名单**（便宜、广撒网）：对每个已生效板块，取 ①新浪题材里名称与板块相近的成分股（只当候选）；②近期晚报里该方向点名的股票（`hi189.parse_sectors` 的涨停板/强势股，按名称对到代码）。
2. **纯度判定**（用数据，不靠印象）：
   - 取候选股的**主营构成**（东方财富 F10 `akshare.stock_zygc_em`，按产品拆分的收入与占比，最近一期报告）。
   - 让 Jev 做选择题：每个产品行属于哪个已生效板块（或「都不是」），缓存到 `own_product_map(product_text, sector_id)`，同一产品名不重复问。
   - 把映射到同一板块的产品行占比相加：≥50% → `core`；30%～50% → `related`。
3. **没有构成数据的票**（新股、数据缺失）：取主营业务介绍（`akshare.stock_zyjs_ths`），让 Jev 读后判断「核心产品是否属于该板块」，写 `pending` + 依据，等用户确认，**确认前不算 core**。
4. **文章事件标签**：晚报/研报里提到该股的订单、业绩、大事，摘要存进 `basis.events`（带文章链接和日期），只展示，不参与是否入板块的判断。
5. **预算与节奏**：构成数据按股票缓存，**新财报期或 30 天才刷新**；每天收盘后跑，有时间上限（像公告正文预抓，`OWN_SECTORS_BUDGET` 默认 600 秒），没跑完下个交易日接着跑。只抓候选股，不扫全市场。

## 龙头排序（纯代码，不用 Jev）

同一板块的 core 成员，按下面几项名次相加（小者在前），同分看涨幅：
- 当日涨幅、当日成交额、近 5 日涨幅（沿用现有 `leader()` 三项）；
- **纯度**（`share` 高的优先）；
- 最高连板数/是否首板涨停。
权重先等权，记录里留每项名次，方便事后换权重重算。前 N 名（`OWN_SECTORS_LEADERS=6`）写进日快照。

## Jev 判断板块强弱

- 每个板块每天最多问一次，收盘后；只问**今天有 ≥ 3 只 core 成员涨超 5% 或晚报点名**的板块，控制调用量。
- state：成员数、强势数、涨停数、平均涨幅、成交额较前一日变化、最高连板、是否被晚报点名；选项同情绪：`冰点/偏弱/正常/火热`，用现有 `score` 题型，结果和概率都记下。
- 失败 → 记 `jev_strength=null`，不重试、不影响其他记录。

## 面板与报告

- 新增「自建板块」页（只读，沿用「候选」页的做法）：板块列表（成员数、当日强势数、Jev 强弱、龙头前三）→ 点进去看成员表（占比、依据、tier、状态）、龙头顺序、近期事件；`proposed` 板块和 `pending` 成员单独成区，可确认/驳回（这两个动作是本功能唯一的写操作，只写自建板块自己的表）。
- 复盘报告加一小节「自建板块（只记录）」：当天 Jev 判为偏强/火热的板块和龙头前三。

## 验证计划（决定要不要用到选股上）

本版只负责积累。攒到约 20 个交易日后再看，回答这几个问题（不在本版实现，只保证数据够用）：
1. 自建板块的「强势日」和新浪题材的「热门日」是否一致，哪边更能提前指出次日强势？
2. 龙头 1～3 次日表现（高开/收盘/连板率）是否优于同板块其他成员和新浪口径选出的龙头？
3. Jev 判「火热/偏强」的板块，次日板块平均表现是否更好？
4. core 的占比线（50%）放宽到 40% 或收紧到 60%，结果差多少（所以 `related` 也记）？
下一份 spec 再决定「影子选股记录」和是否接入策略。

## 风险与限制

- **数据可得性未验证**：`stock_zygc_em` 在云端沙箱访问不了（东方财富域名被网络出口挡住），**必须先在家里电脑实测**（单独一个只读探测脚本 `scripts/own_sectors_probe.py`，不下单、不写库），确认能取到、字段名、占比口径，再上线。取不到则退回「Jev 读主营介绍」路径，全部走 `pending`，需要更多人工确认。
- 收入构成按**财报期**披露，最新一期可能是半年报：刚转型的公司会漏、转型失败的公司会多。所以每条都带报告期和有效期。
- Jev 做产品→板块映射可能出错：缓存后同一产品名永远同一结论，所以**映射表要能在面板里查看和修正**（修正后相关成员重算）。
- 「主业」的产品名称五花八门（电子布/玻纤布/特种布）：板块的 `product_def` 要写具体，必要时补别名。
- 数据量：几十个板块 × 数百候选股，表很小；`own_sector_daily` 每天几十行。

## 变更点（实现范围）

- `jevq/data/own_sectors.py`：表、种子加载、候选生成、构成抓取与缓存、纯度判定、龙头排序、日快照。
- `jevq/judge/own_sectors.py`：产品→板块映射、主营介绍判断、板块强弱（都走 `JevClient.ask`）。
- `run.py`：收盘后（报告生成之后）一步，带预算与 try/except；不碰交易循环。
- `jevq/app/api.py` + `ui.html`：「自建板块」页；`report.py`：一小节。
- `jevq/config.py`：`OWN_SECTORS_ENABLED`、`OWN_SECTORS_BUDGET`、`OWN_SECTORS_LEADERS`、占比线 `OWN_SECTORS_CORE_SHARE=50`、`OWN_SECTORS_RELATED_SHARE=30`。
- 四处同步清单：config、`api.builtin_summaries`（这是只记录功能，不是交易策略，**不进**策略说明，只在 HANDOFF 新增一节说明）、HANDOFF、相关设计文档变更记录（本文）。
- 测试：构成数据用夹具（不联网）；纯度判定的边界（=50%、多产品相加、缺数据）；龙头排序；日快照；与交易隔离（前后 decisions/fills 不变）；页面渲染与转义。

## 不做

- 不接任何策略、不影响实盘；不自动创建板块；不扫全市场；不用 Jev 排龙头；本版不做影子选股与结果对比。
